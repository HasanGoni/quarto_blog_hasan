VFlash: Fast, Accurate Visual Planning via Flash Primitive Decoding

arXiv 2611.08449 · picked for the week of 2026-11-06 · VFlash offers a concrete method for fast, accurate visual planning using bounding boxes and points, which directly enhances the localization capabilities of small VLMs like Qwen3-VL for defect detection.

arXiv HF paper page

VFlash is a decoding framework that speeds up visual planning in robotics and driving by predicting entire geometric shapes (like boxes or trajectories) in one parallel pass rather than token-by-token. It achieves this by aligning the prediction structure with known visual primitives, resulting in faster latency and often higher spatial accuracy compared to standard autoregressive models.

Explain it simply

Explain it like I'm five

Imagine you are drawing a picture of a house. Usually, a computer draws it one tiny line at a time, which is very slow. VFlash is like a magic stencil that lets the computer draw the whole roof or door in one quick swoop. It knows exactly where the lines should go because it has seen the shape before. This makes the computer think and draw much faster. It also draws the house more accurately because it doesn't get confused by drawing one line at a time. So, the robot can see and plan its moves quickly, like a superhero.

Explain it like I'm a data scientist

The core problem is that autoregressive Vision-Language Models (VLMs) generate spatial plans (bounding boxes, trajectories) sequentially, one coordinate token at a time. This creates a latency bottleneck for physical AI systems that need to update plans frequently under strict time budgets, and the sequential nature can lead to accumulated errors in spatial accuracy.

VFlash introduces Flash Primitive Decoding (FPD), which uses a lightweight diffusion drafter to predict an entire visual primitive in a single forward pass. By leveraging the known structure of the primitive (type, dimensionality, length), the method aligns draft blocks with primitive boundaries and accepts structurally valid predictions directly, bypassing the need for token-level agreement with the target model. This allows for parallel decoding of spatial data while retaining verified speculative decoding for text, significantly reducing inference latency.

The system identifies the type and structure of the required visual primitive.

Given visual observations and a task instruction, the VLM determines the schema for the prediction. This includes the primitive type (e.g., box, trajectory), its dimensionality (2D/3D), and its extent (length). For variable-length predictions, a tool call declares the specific size.

The decoder sets up a prediction block aligned with the primitive's boundaries.

Based on the schema, the system defines a block of length B(s) consisting of a start token and masked positions for the coordinates. This layout ensures that the entire geometric object is treated as a single unit for parallel prediction, avoiding splits caused by fixed-length windows.

A lightweight diffusion drafter predicts all coordinates in a single forward pass.

Conditioned on features from the frozen target VLM, the drafter generates the entire block of masked tokens simultaneously. This replaces the sequential autoregressive process with a parallel one, significantly reducing the number of forward passes needed for the spatial data.

The system validates the drafted primitive against structural and spatial constraints.

Instead of checking for token-level agreement with the target model, VFlash applies layout-specific constraints and a schema validator. For bounding boxes, a spatial-confidence guard is also used. If the prediction is structurally valid, it is accepted directly.

Valid primitives are committed without further verification.

If the acceptance test passes, the entire primitive is committed to the output. This bypasses the need for the target model to verify each token individually. If the test fails, the system falls back to constrained autoregressive decoding for the invalid parts.

The target VLM updates its context for subsequent predictions.

After accepting the primitive, the target VLM performs a single forward pass to update its cache and context features. This ensures that subsequent predictions (whether text or further primitives) have access to the newly generated spatial information.
