# nbdev tutorial video: "five mistakes, five fixes" (design)

Status: draft for the author's review. Nothing is built yet beyond two spikes (Motion Canvas render, nbdev setup).

## Intent
- **Audience:** people who already use nbdev but use it wrongly (A) and newcomers who want a correct first project (B).
- **Style:** wrong-vs-right pairs (C). Each chapter shows the common mistake, then the fix, then one memorable sentence.
- **Outcome:** after the video a viewer can create a project the right way, work notebook-first, ship a CLI, add libraries with uv, and keep the repo clean with tests and hooks.
- **Voice and delivery:** the author's cloned voice, calm and warm tone per chapter, word-by-word subtitles, per-chapter review in the browser, three cuts at the end (calm, warm, mix). Same flow as the management video.

## Story (pyramid: answer first), about 7-9 minutes
| # | Chapter | Wrong | Right |
|---|---|---|---|
| 0 | Intro | - | Name, topic: "nbdev, the right way" |
| 1 | Answer | "nbdev is just a Jupyter export tool" | Notebook = library + tests + docs. Five mistakes, five fixes. |
| 2 | Setup (what the lines create) | `uv init`, hand-made venv, activating by hand | `uvx --from nbdev nbdev-new --min-python 3.12`, `uv add --dev nbdev`, `uv run ...`; the folder structure nbdev enforces and what each part is |
| 3 | M1 Explore first, then function | Write the function first, hope it works | Try in cells, see output, then wrap in a function, then `#\| export` |
| 4 | M2 Never edit the generated `.py` | Fix the exported library file | Edit the notebook; where modules land (`#\| default_exp`, `lib_path`/`nbs_path`); what `nbdev-update` can sync back (verify) |
| 5 | M3 CLI from a notebook function | Hand-written argparse | A console command from a notebook function (mechanism verified before writing) |
| 6 | M4 Libraries with uv | `pip install` plus hand-edited config | `uv add` (own library or third-party), what changes in `pyproject.toml` and `uv.lock` |
| 7 | M5 Tests and hooks | No tests, messy notebook diffs, broken merges | Tests in notebooks, `nbdev-test`, `nbdev-install-hooks`, readable merge conflicts, `nbdev-prepare` before every commit |
| 8 | Close | - | Rapid list (`nbdev-prepare`, `nbdev-preview`, `nbdev-release-gh`, `nbdev-pypi`, `nbdev-changelog`) and one docs line: the notebook is the doc |

Rule from the management video still applies: every drawn item is also spoken, nothing is said twice, chapters appear exactly when their words are spoken.

## Truth rule
Every command is run first in the demo repo (`HasanGoni/nbdev-tutorial`, created empty on 2026-10-16) and the on-screen output is the captured real output. Versions pinned in the video: nbdev 3.3.25, uv 0.11.26 (re-check on build day). Anything not verifiable is cut or labelled.

### Already verified (2026-10-16)
- `uvx --from nbdev nbdev-new --min-python 3.12` writes files only (no venv): `nbs/` (`00_core.ipynb`, `index.ipynb`, `_quarto.yml`), library folder, `pyproject.toml` (`[tool.nbdev]` empty = defaults), `.github/workflows/{test,deploy}.yaml`, `README.md`, `LICENSE`, `.gitignore`; `requires-python = ">=3.12"`; repo name/user inferred from git.
- `uv add --dev nbdev` creates `.venv` (Python 3.12), `uv.lock`, `[dependency-groups] dev` and an editable install of the package.
- `uv run nbdev-export` / `uv run nbdev-test` work without activation (`which nbdev-export` is empty outside `uv run`).
- Generated `core.py` carries "AUTOGENERATED! DO NOT EDIT! File to edit: ../nbs/00_core.ipynb"; first notebook cell is `#| default_exp core`.
- Config defaults: `lib_path` = `./<package>`, `nbs_path` = `./nbs`, `doc_path` = `./_docs`.

### To verify before each chapter is scripted
- M2: what happens to a hand-edit of `core.py` on the next `nbdev-export`; behaviour of `nbdev-update`; overriding `lib_path`/`nbs_path` in `[tool.nbdev]`; dotted `default_exp sub.module` for subfolders.
- M3: the exact CLI mechanism in nbdev 3 (expected `fastcore.script.call_parse` plus a `[project.scripts]` entry) and the command that registers it; run the resulting command through `uv run`.
- M4: `uv add` of a PyPI library, of a local/own library (path or git), and what nbdev's `pyproject.toml` dependency handling expects (`dependencies` vs the dev group).
- M5: notebook tests (`nbdev-test`, directives such as `#| eval: false`), `nbdev-install-hooks`, `nbdev-merge`/`nbdev-fix` on a real conflict, `nbdev-prepare` output.
- Close: `nbdev-preview` (needs Quarto: check install), release commands only described, not executed against PyPI.

## Visual design and tool choice
No default tool. Per chapter we decide together (see skills `narrated-manim-video`, `narrated-motion-canvas-video`). Proposed starting point, to be confirmed chapter by chapter:
| Chapter | Proposed tool | Why |
|---|---|---|
| 0, 1 | Motion Canvas | text and card layout, quick iteration |
| 2 Setup | Motion Canvas | terminal panel with replayed real output, file tree that fills in per command |
| 3-5, 7 | Motion Canvas | wrong-vs-right split screens, notebook and terminal panels |
| 4 (export flow) | open: Manim if a zoom tour of the folder tree reads better | decide when scripting it |
| 6 | Motion Canvas | `pyproject.toml` before/after |
| 8 | Motion Canvas | rapid list |
Shared rules: **yellow only for the subtitle highlighter**; other text white or accent cyan `#6EC6FF`; wrong = red/orange card, right = green card; terminal panels replay captured text exactly as run, typed in step with the words; no minimap; content above the subtitle band.

## Pipeline and files
- Voice, timestamps, chapters, approval, cuts: reuse `videos/make_chapter.sh` stages and `approve_chapter.sh`, `join_cut.sh` (new slugs, new story files, e.g. `videos/nbdev/story_order.txt`). Motion Canvas chapters follow the `narrated-motion-canvas-video` recipe (audio + `timeline.json` in, frames out, ffmpeg to 1280x720 30 fps h264/aac so cuts can mix tools).
- Narration lives in each chapter file's `LINES` (we-voice, short, 1-3 marked words).
- Pronunciation, to be decided by listening tests with the author: "nbdev", "uv", "uvx", "nbdev-new", "pyproject". Set once in `video_speech.spoken()` and recorded in the video-review memory.
- Demo repo `HasanGoni/nbdev-tutorial`: each chapter's state is reproduced in a local clone first. Pushing to GitHub happens only when the author says so.
- A new skill `nbdev-tutorial-video` is NOT planned; learnings go into the two existing video skills.

## Review flow
1. Build chapter 0 and 1 (calm and warm), author reviews in `chapters/index.html`.
2. Then chapters 2-8 one by one: verify commands, script narration, show script for approval, build both tones, author approves.
3. Three cuts: calm, warm, recommended mix (warm for hook and close, calm for command-heavy chapters). Send to Discord only when asked.

## Success criteria
- Every command and output on screen was run by us and matches the installed versions.
- Each chapter: spoken words, subtitles and visuals in sync (frame checks at word boundaries + whisper transcript), no overlap or clipping, no yellow outside subtitles.
- A newcomer following only the video can create the project, export a notebook, run a CLI, add a library and run tests.
